# Electron Benchmarks 产品方案

更新日期：2026-10-20

本文保留早期产品方案与讨论结构，其中 HTML 等展示设想已被面向 AI 的结构化输出取代。当前产品约定和首期实现以 [PRD](PRD.zh-CN.md) 为准，验证范围见[实现记录](IMPLEMENTATION.zh-CN.md)。

## 1. 定位与范围

Electron Benchmarks 是可复现的 Electron 性能基准测试套件，用固定场景评估 Electron 自身的性能，比较版本差异，验证优化效果。

支持单版本测试和多版本对比。单版本测试给出指标、原始样本和环境信息；多版本对比在同一环境下运行相同场景，给出各版本数据，以及相对基准版本的绝对差值和变化百分比。

第一阶段只做启动、内存和 CPU 的基准测量。trace、profiling 等诊断采集留到以后，也暂不支持测试任意用户应用。

主要使用者及其任务如下：

| 使用者 | 任务 |
| --- | --- |
| Electron 维护者 | 比较发布版本或修改前后的本地构建，查看性能差异和样本波动 |
| Electron 应用开发者 | 比较不同版本在标准场景下的基础性能 |
| 测试贡献者 | 在自己的机器上复现实验，提供可复核的数据 |

测试结果对应具体场景和环境，不能直接代表真实业务应用的表现。

## 2. 使用方式

以 CLI 为入口，用 JSON 保存测试配置，在本地查看 HTML 报告。CLI 名称为 `electron-benchmarks`。通过 npm 包分发。第一阶段不做桌面 GUI、在线服务或持续性能看板。

### 2.1 命令形式

参考 Crossbench，以测试名作为命令入口：

```text
electron-benchmarks <test[:scenario]> --electron <version-or-path> [options]
```

支持 `startup`、`startup:warm`、`startup:cold`、`startup:all`、`memory`、`cpu` 和 `all`。`startup` 等价于 `startup:warm`，`startup:all` 只执行冷热启动。以下示例说明命令用法，版本号仅用于说明输入形式。

`all` 包含冷启动、热启动、内存和 CPU 测试。开始前检查冷启动条件并展示完整测试及重启安排，用户确认后执行；先完成冷启动，再在最后一次开机内完成热启动预热与测量，最后执行资源测试。顺序沿用拆分 PR 的测量经验，避免整批热启动改变冷启动的历史条件。

```powershell
# 单版本热启动测试
electron-benchmarks startup:warm --electron 40.0.0
```

只传一个目标就做单版本测试，重复传入 `--electron` 就做多版本对比：

```powershell
electron-benchmarks startup --electron 39.0.0 --electron 40.0.0 --electron 41.0.0
```

固定以第一个目标为基准，其他目标分别与它比较。执行前显示全部目标和基准，调整参数顺序即可更换基准。

### 2.2 常用选项

| 选项 | 用途 | 默认行为 |
| --- | --- | --- |
| `--electron` | 版本号或本地构建路径，可重复 | CLI 模式下必填 |
| `--repeat` | 每个目标、每个场景的正式运行次数 | 启动测试每种冷热条件各 20 次，资源测试次数待定 |
| `--out` | 结果目录 | 自动创建本次运行的独立目录 |
| `--config` | 从 JSON 读取测试配置 | 作为 CLI 参数的另一种输入方式 |
| `--help` | 查看用法、场景和指标说明 | 不执行测试 |

`--electron` 支持传入精确的发布版本号和本地 Electron 可执行文件路径，两种形式可以混用。

```powershell
# 发布版本与本地构建对比
electron-benchmarks startup --electron 40.0.0 --electron "D:\builds\candidate\electron.exe"
```

发布版本自动下载并缓存，本地构建直接使用。下载、解压和场景准备均在计时前完成。

本地构建可能有相同的版本号。工具自动生成目标 ID，并记录路径和构建身份，区分修改前后的构建。

第一版只接受精确版本号。`latest`、版本范围和发布渠道别名留到后续扩展。

启动测试通过 `startup:warm` 和 `startup:cold` 区分热启动与冷启动，`startup:all` 同时运行两者。例如，比较发布版本和本地构建的冷启动耗时，每个目标正式运行 10 次：

```powershell
electron-benchmarks startup:cold --electron 40.0.0 --electron "D:\builds\candidate\electron.exe" --repeat 10 --out ./results/startup-cold
```

这次实验以 `40.0.0` 为基准，结果保存到 `./results/startup-cold`。冷热启动的缓存、profile 和预热规则分别定义。

冷启动任务固定工具版本和持久运行路径，跨重启使用同一份工具及运行依赖，不依赖临时目录或每次重新解析的最新版本。工具版本或路径发生变化时停止后续测试。

`repeat` 只计算正式运行次数，不包含预热。每个场景使用自己的预热和采样设置，实际设置在执行前和报告中列出。

查询功能集中到 `--help`，第一版不增加 `list`、`describe` 或采集器配置命令。

### 2.3 配置文件

需要重复执行同一实验时，将设置保存为 JSON：

```powershell
electron-benchmarks --config benchmark.json
```

```json
{
  "test": "startup",
  "electrons": ["40.0.0", "D:/builds/candidate/electron.exe"],
  "repeat": 30,
  "out": "./results/startup-warm"
}
```

配置字段与 CLI 对应，`electrons` 的顺序决定基准，目标 ID 由工具生成。

配置配套 JSON Schema，支持字段校验和编辑器提示。第一版中，配置文件与测试 CLI 参数不混用，避免同一设置出现在两处。配置扩展方式待定。

## 3. 测量内容

场景固定测试负载和运行条件，并带有版本号，方便判断新旧结果是否可比。启动保留冷热两种场景；内存和 CPU 第一版使用单窗口空闲负载。

| 测试 | 场景方向 | 测量内容 |
| --- | --- | --- |
| `startup` | `warm` / `cold`：单窗口加载固定本地 SVG 与视频页面 | APP READY 与首次可见视频回调耗时 |
| `memory` | 单窗口空闲 | 固定观察期内的各进程和进程组内存 |
| `cpu` | 固定页面空闲 | 固定观察期内的 CPU 时间和平均占用 |

### 3.1 启动

沿用拆分 PR 后期的计时口径：父进程调用 `spawn()` 紧前起算，测至主进程 `app.whenReady()` 回调入口和标准页面首次有效的可见视频回调。APP READY 是默认主指标；视频回调不代表解码第一帧或物理屏幕输出。完整定义见[技术方案：测量与统计](TECHNICAL-DESIGN.zh-CN.md#2-测量与统计)。

冷启动每个样本前重启，保留 Windows 默认缓存与预取历史。每个目标准备时预检一次，正式测量使用初始 profile 的独立副本，文件完整校验放在测量后。热启动每个目标预热 5 次，并在同一次开机中完成正式测量。默认每种冷热条件各 20 次，输出 P50/P90 和逐轮数据。

### 3.2 内存与 CPU

内存报告保留各进程数据和进程类型，包括实际存在的 main、renderer、GPU、utility 等进程。汇总时说明所用指标和共享内存的处理方式。不同平台的指标需保留各自口径，不能只给一个没有解释的“内存 MB”。峰值是否纳入、稳定观察期如何定义，还需讨论。

CPU 测量需要确定观察期、采样方式和占用百分比的分母，例如按单个逻辑核还是整机容量归一化。

启动、内存和 CPU 分别运行，避免资源采样影响启动测速。

## 4. 运行流程与结果

### 4.1 一次实验如何执行

1. 校验参数、目标及平台支持情况。
2. 下载或定位 Electron，准备标准场景和运行目录。
3. 显示目标、基准、场景、预热和正式运行次数。
4. 执行测量，每完成一次运行就保存记录。
5. 清理被测进程，汇总结果并生成报告。

多版本在同一机器上逐个运行，按轮次轮换顺序。调度方法固定并写入记录，避免并发测试争抢资源。

每次实验保存工具和场景版本、最终配置、系统与硬件信息、目标身份、启动参数，以及 profile、缓存、预热、采样和执行顺序。原始样本还需包含成功或失败状态、失败原因和测量日志。

失败样本不记为零，异常样本不静默删除。采用剔除规则时需说明原因。实验中断后保留已完成的样本，并标记为未完成；平台不支持的指标标记为不支持。

### 4.2 输出形式

| 输出 | 内容 |
| --- | --- |
| 终端摘要 | 主要指标、基准差值、成功与失败次数、报告位置 |
| HTML 报告 | 各版本汇总、样本分布、版本差异、环境信息和进程明细 |
| JSON | 带协议版本的指标、配置和实验状态 |
| 原始记录 | 每次运行的数据，供复核与重算 |

多版本报告默认将每个目标与基准比较，暂不生成所有版本两两比较的矩阵。

绝对差值为目标值减去基准值，变化百分比为差值除以基准值再乘以 100%。基准为零时，百分比标为不可计算。报告应说明每个指标增减的含义，并展示样本数量和波动。

启动测试采用固定方法计算 P50/P90，资源测试的统计预设仍待验证。百分比变化本身不足以确认性能回归，首期不输出显著性结论。离线重算报告是否纳入第一版待定。

## 5. 实现方向

采用 TypeScript / Node.js，提供 CLI，通过 npm 包分发。标准场景定义负载和运行条件，独立的 Runner 执行测试，Reporter 输出结果。被测 Electron 只运行标准场景和必要的测量标记。

进程控制、时间标记和平台采集的具体实现放到技术设计中说明。

第一期只支持 Windows。macOS、Linux 放入 [Todo.md](../Todo.md)，后续再扩展。

## 6. 待确定的事项

| 事项 | 需要确定的细节 |
| --- | --- |
| Windows 支持范围 | Windows 最低版本和支持架构 |
| 资源测量 | 内存指标与汇总方式、CPU 归一化方式、观察期和采样频率 |
| 资源测试预设 | 内存、CPU 的预热、正式次数和汇总统计量 |

| 首期报告 | HTML 做到什么程度，是否支持离线重算 |

首期验收标准：一条命令在同一机器上测量三个 Electron 目标的同一标准场景，输出各目标指标、相对基准的差值，以及可复核的样本和环境记录。
