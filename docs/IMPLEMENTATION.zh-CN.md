# 首期实现与验证

更新日期：2026-10-20

## 实现范围

- Windows 10/11 x64 CLI，TypeScript / Node.js，原生辅助程序为 C++。
- 精确版本下载与缓存、本地构建、单版本和多版本共用执行流程。
- 热启动、重启后冷启动、单窗口空闲内存与 CPU；`all` 固定先冷后热，再运行资源测试。
- 冷启动临时 HKCU Run、固定工具与 Node 副本、独立重启周期、输入校验、正常续跑和异常终止。没有计划任务，也没有自动登录设置操作。
- 每次样本独立落盘，P50/P90、基准差值、HTML 与 JSON 报告。

## 代码复用

从 `electron-windows-runtime-benchmark` 迁入并适配：

- 父进程发起启动前计时、QPC/FILETIME 桥接和渲染进程时钟校验。
- 本地 SVG、720p 视频、首次视频回调及可见性校验。
- 冷启动条件、Normal/2/5 优先级要求、先冷后热与逐轮数据原则。

没有复制旧报告中的性能结论。媒体来源和许可证保留在 `harness/`，代码来源见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

本地 GN 构建目录包含大量编译中间文件，输入指纹只覆盖 Electron 运行资产，排除 `obj/`、PDB、无关测试程序和编译缓存。每个正式样本后的完整校验会读热文件，因此冷启动的下一样本必须重新启动系统。

## 资源指标

内存使用 Electron 各进程的 Windows 私有提交量和工作集。观察期采样峰值与进程生命周期峰值分开解释。

本地构建首个 `percentCPUUsage` 区间实测出现过负值，原始数据未截零。正式 CPU 指标改用只读原生观察器取得各进程 `GetProcessTimes` 的首尾差值，按 QPC 实际时长和逻辑处理器数归一化。进程在观察期间消失或重建则失败，避免将不完整区间写成零消耗。

## 验证边界

自动化测试不注册自启动、不重启、不启用或关闭自动登录。冷启动执行必须在交互终端中确认完整重启安排。

完整实体机跨重启验收仍在 [Todo.md](../Todo.md)。模拟的计划和状态边界测试不能代替真实重启链路验证。当前开发机测试采用缩小的正式样本数，只验证行为和数据路径，不形成版本性能结论。
